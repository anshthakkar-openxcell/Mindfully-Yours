## Clinical/product terms

| Term | Meaning |
|---|---|
| **Silent triage** | The AI's continuous, invisible reading of the conversation for severity signal — no questionnaires, no visible scoring. Runs every turn. |
| **Safety interlock** | The deterministic, rule-based system that detects crisis language and can force escalation, independent of the LLM. Never skipped. |
| **Grounding** | Confirming the LLM's output is actually supported by the retrieved KB passage, not just plausible-sounding. Checked in the output guardrail. |
| **Graceful exit trigger** | The specific evidence combination that ends probing for a pattern, even if the tier threshold isn't technically "complete." |
| **Sufficiency check** | The lookup that determines whether accumulated signals meet a pattern's minimum/must-have threshold for a tier decision. |
| **Fallback & Safety Net** | The third response type for conversations that are vague, contradictory, or disengaging — distinct from both "keep probing" and "enough, route now." |
| **Red flag** | A crisis/danger trigger phrase (direct or disguised) that forces immediate Tier 3/SOS routing, bypassing normal probing. |
| **Bot script** | Client-authored, verbatim wording for a red-flag or fallback response — never paraphrased or regenerated by the LLM. |
| **Two-tier cache** | Exact-match/FAQ cache (tier 1) then semantic cache (tier 2), checked before any retrieval/generation. The primary cost lever in the system. |
| **Filler phrase** | A short natural utterance ("Hmm…", "Let me think about that…") played to mask processing latency, selected by situation type, never exposing implementation details. |
| **Chunk** | The atomic retrievable unit stored in the vector database — for most KB sheets, one row = one chunk. |
| **Provider-abstraction layer** | The common interface application code calls for any external AI capability (LLM/STT/TTS/avatar/embeddings), so vendor swaps never touch business logic. |
| **DPDP** | India's Digital Personal Data Protection Act — the regulatory regime this platform is built to, explicitly *not* HIPAA. |
| **Protected Information** | The contract's (Clause 4.7) highest-protection data category: clinical KB, clinical content, mental-health info, conversation records, Personal/Sensitive Personal Data. |

## Architecture/tech terms

| Term | Meaning |
|---|---|
| **RAG** | Retrieval-Augmented Generation — retrieve grounded content first, then let the LLM phrase it; never let the model invent clinical guidance from general training. |
| **pgvector** | PostgreSQL extension enabling vector similarity search, used so relational and embedding data live in one datastore. |
| **Room** (LiveKit) | A real-time session container — every AI Companion conversation, practitioner consultation, and SOS call is its own Room. |
| **Participant** (LiveKit) | Anyone/anything publishing or receiving media in a Room — a user, or the AI itself as a server-side participant. |
| **Egress** (LiveKit) | LiveKit's built-in recording feature, writes directly to S3 — used only for practitioner/SOS calls, never every AI Companion turn. |
| **Barge-in** | The user interrupting the AI mid-response — handled by LiveKit's Agents framework, not custom-built. |
| **Time-to-first-token** | How quickly the LLM starts streaming output — usually the single biggest latency contributor. |
| **P50/P95/P99** | Latency percentiles — optimize for the tail (P95/P99), not just the average, since a long tail of slow outliers still feels broken to the users who hit it. |
