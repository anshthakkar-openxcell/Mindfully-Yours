# 36 — Safety Interlock Rules: what the client wants, and how we implement it

**Source:** `documnets/new uploaded documents/Safety Interlock rules.docx` (client, received 2026-10-21).
**Related:** [08_SAFETY_INTERLOCK_AND_TRIAGE](08_SAFETY_INTERLOCK_AND_TRIAGE.md), `backend/app/safety/interlock.py`, `backend/app/pipeline/guardrail.py`.

## 1. In one minute

The client's document is a **safety spec**: a list of things the AI must never say or do (rules R1–R16),
plus the system-level controls that keep it safe in production (S1–S9).

How to read it:
- **R-rules = what the AI must not do.** Each one has a *how to implement* hint and an *action*.
- **S-controls = the safety machinery around the AI** (kill switch, alerts, logging, config, testing, compliance).
- **Actions** — STOP: halt, send the fallback or crisis template, log it. BLOCK: discard the draft, regenerate (max 2 tries), then fall back. IGNORE: do not comply, redirect safely, log it.
- Treat it as an **acceptance checklist**: every rule gets a test, and we are not done until each rule has one.

## 2. The flow it prescribes

1. **Input gate** (before the LLM): screen user text, uploads, pasted text and retrieved content for risk and injection.
2. **Draft**: the LLM writes a reply, buffered, never streamed before approval.
3. **Output gate**: toxicity, scope, privacy and rule checks on the draft.
4. **Decision**: Pass sends it. Borderline regenerates once with a safer prompt. Fail goes to the stop handler.
5. **Stop handler**: discard the draft, send a pre-approved fallback (plus crisis resources if there is risk), log it, flag for a human if severity is high.

Principles: **fail closed** (any check error or timeout is a Fail), **never go silent** (the user always gets help or resources), **fixed templates** (fallbacks and crisis messages are pre-written, never generated by the model).

## 4. System controls

| ID | Control | Implementation note |
|---|---|---|
| S1 | Repeated-violation counter | Per session; at a clinician-set threshold (suggest 3) move to safe mode and flag for review |
| S2 | Crisis resources | Region-wise **config file**, not hardcoded. India candidates: Tele-MANAS 14416, KIRAN 1800-599-0019, 112, Childline 1098. Verify before launch. |
| S3 | Human escalation | On-call clinical reviewer queue for R3, R4, R5, R11; SLA to be agreed with the clinical lead |
| S4 | Kill switch | Server-side flag checked on every request. L1 feature pause, L2 safe mode (scripted replies only), L3 full shutdown with a static helpline page. Founders only; reactivation needs two-person approval; MFA + audit trail. |
| S5 | Auto-trip alerts | Alert founders on a block-rate spike, an interlock health-check failure or undeliverable crisis resources. Failure triggers fail-closed, not silence. |
| S6 | Logging | Rule ID, timestamp and session ID **only**; encrypted; retention under the DPDP Act |
| S7 | Config control | Rules and thresholds in versioned config; clinical sign-off by both founders; the model can never edit them |
| S8 | Testing | Regression tests per rule ID; red-team before each release incl. Hinglish; new thresholds run in shadow mode first |
| S9 | Compliance | DPDP Act 2023, Mental Healthcare Act 2017, Telemedicine Practice Guidelines, incident reporting; confirm with counsel |

## 6. Implementation plan (suggested order)

1. **Rule registry + config (S7, S2):** one versioned config file keyed by rule ID (action, thresholds, phrase lists), and a region-wise helplines file. Nothing hardcoded.
2. **Output gate (`app/safety/output_gate.py`):** one post-draft step running R4, R6, R7, R8, R10, R12, R16. Start with phrase lists, add a light classifier later. Returns Pass / Borderline / Fail plus the rule ID. Wire in the regenerate-once-then-fallback loop, and fail closed on any exception or timeout.
3. **Input intent checks:** R2 (diagnosis/medication), R3 (harm to others), R9 (injection). Run in parallel with retrieval so they add no latency. Treat retrieved text as data.
4. **Session state (R14, S1):** a `risk_flag` that forces supportive mode with resources, and a violation counter that moves the session to safe mode at the threshold.
5. **Real grounding check (R13):** replace the placeholder in `guardrail.py`.
6. **Logging (S6):** rule ID, timestamp, session ID only; never message text.
7. **Tests (S8):** `tests/unit/test_safety_rules.py`, at least one passing and one failing case per rule ID, including Hinglish. Shadow mode for new thresholds.
8. **Infrastructure (S3, S4, S5):** kill-switch flag checked per request, clinician escalation queue, alerting. Agree the owners and the tooling with the client first.
