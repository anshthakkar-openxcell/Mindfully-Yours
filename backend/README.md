# Mindfully Yours — AI Service

The Python/FastAPI AI service for Mindfully Yours: the RAG conversation pipeline, silent triage,
safety interlock, KB ingestion, and provider-abstraction layer.

**Scope**: this repo is the AI service *only* — no frontend, no NestJS backend. See
`documnets/understanding/14_FEATURE_BREAKDOWN_AND_IMPLEMENTATION_PLAN.md` for the exact scope
line and the API contract this service exposes to the (out-of-scope) backend.

**Before writing any business logic, read `documnets/understanding/00_INDEX.md` first.** Every
module below has a docstring pointing at the specific design doc that governs it — this is not
optional context, it's the spec.

## Project layout

```
app/
  main.py                 FastAPI app factory, health check, router mounting
  core/                   config, logging, exceptions, security (trusted-caller auth)
  db/                     SQLAlchemy async models + session, matching 11_DATA_MODEL_AND_STORAGE.md
  schemas/                Pydantic request/response models for the API layer
  api/v1/                 HTTP routes -- the AI service's external contract
  pipeline/               Epic D: the 14-step runtime conversation pipeline (04_CONVERSATION_PIPELINE.md)
  safety/                 Epic C: silent triage + safety interlock (08_SAFETY_INTERLOCK_AND_TRIAGE.md)
                           -- build and test this in isolation, first, per 01_PROJECT_OVERVIEW.md principle #2
  ingestion/               Epic B: offline KB ingestion + signal enrichment (06/07_*.md), run via CLI, not the API
  providers/               Provider-abstraction layer (02_ARCHITECTURE.md §2) -- LLM/STT/TTS/Embeddings/Avatar
                           adapters live here; application code never imports a vendor SDK directly
  realtime/                Epic G: the LiveKit Agent process for AI Companion voice/avatar (10_LIVEKIT_REALTIME.md)
                           -- practitioner/SOS room management is NOT here, it's out of scope
  workers/                 Async, non-blocking background tasks (audit logging, summaries) -- 09_LATENCY_AND_PERFORMANCE.md §8
alembic/                   DB migrations
scripts/                   One-off/dev scripts (e.g. seeding a dev KB from synthetic fixtures)
tests/                     unit/ (safety + pipeline logic in isolation), integration/ (full pipeline),
                           fixtures/synthetic_kb/ (synthetic data ONLY -- never real KB/user data, per
                           documnets/understanding/12_SECURITY_COMPLIANCE_DPDP.md §8)
```

## Getting started

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env   # fill in real vendor keys -- confirm no-training/no-retention tier first (12_SECURITY_COMPLIANCE_DPDP.md §1)

# Postgres + pgvector and Redis must be running (docker-compose not yet added -- see TODO below)
alembic upgrade head

uvicorn app.main:app --reload
# → GET http://localhost:8000/api/v1/health
```

Run tests:
```bash
pytest
```

Run the ingestion CLI (Epic B) against the real KB sheets in `documnets/knowledgebase/`:
```bash
python -m app.ingestion.cli --help
```

## Ground rules (do not relitigate these — see the linked doc for why)

- **The safety interlock (`app/safety/`) is never skipped, never bypassed, never delegated to the LLM, and always fails toward the more cautious path.** — `documnets/understanding/01_PROJECT_OVERVIEW.md` principle #2, `08_SAFETY_INTERLOCK_AND_TRIAGE.md`.
- **A cache hit still runs triage + interlock.** Caching only ever skips retrieval/generation. — `04_CONVERSATION_PIPELINE.md`.
- **Never call a vendor SDK directly from pipeline/safety/API code** — go through `app/providers/`. — `02_ARCHITECTURE.md` §2.
- **Never paste real clinical KB content or real user data into an AI coding assistant, and never put real user data in a test/dev environment.** — `12_SECURITY_COMPLIANCE_DPDP.md` §7-8. `tests/fixtures/synthetic_kb/` must stay synthetic.
- **Red Flag and Fallback `bot_script` values are fetched verbatim, never regenerated by the LLM.** A flag with no script (RF-028–031 today) routes to a hard human alert, not a silent LLM fallback. — `08_SAFETY_INTERLOCK_AND_TRIAGE.md` §4.
- **Routing rules evaluate in `priority` order (1→2→3), never `rule_id` order.** — `05_KNOWLEDGE_BASE_DEEP_DIVE.md` §4.
